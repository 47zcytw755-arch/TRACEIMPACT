# Storage Architecture & Ingestion Pipeline — TraceImpact Cloud

> **Status Notice:** This document outlines the target storage architecture. Cloudflare R2 storage and live background parsers are **planned for Day 2** and are not connected on Day 1.

---

## 1. End-to-End File Ingestion Flow

```
[ Browser Client ]
        |
        |  1. Request Presigned Upload URL (File name, size, MIME)
        v
[ Secure Ingestion API Endpoint ] (/api/datasets/upload-intent)
        |
        |  2. Validate workspace quota, token & file extension
        |  3. Generate time-limited AWS-S3 compatible presigned URL
        v
[ Cloudflare R2 Object Storage ] (Planned)
        |
        |  4. Direct multipart upload from browser to R2 bucket
        |  5. Webhook / SQS notification upon completion
        v
[ Data Ingestion & Profiling Worker ]
        |
        |  6. Stream file content (Chunked stream)
        |  7. Type inference & quality scoring
        v
[ Structured PostgreSQL / Analytical DB ]
        |
        |  8. Save dataset record, column profiles & quality issues
        v
[ Client Real-Time Update ]
```

---

## 2. V1 Supported File Formats Matrix

| Extension | MIME Type | Parser Strategy | Expected Structure |
|---|---|---|---|
| **.CSV** | `text/csv`, `application/csv` | Streaming CSV parser (PapaParse / Fast-CSV) | Tabular rows with headers |
| **.XLSX** | `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` | SheetJS (xlsx) / ExcelJS stream | Single or multi-sheet workbooks |
| **.JSON** | `application/json` | Streaming JSON parser (JSONStream / oboe) | Array of flat or nested JSON objects |
| **.TXT** | `text/plain` | Delimiter detection heuristic (Tab, pipe, comma) | Delimited records or structured logs |

## 3. Storage Hierarchy & Bucket Naming Strategy

In Cloudflare R2, objects are strictly partitioned by workspace:

```
r2://traceimpact-datasets/
  └── workspaces/
      └── {workspace_id}/
          └── datasets/
              └── {dataset_id}/
                  ├── raw/
                  │   └── {file_uuid}_{original_filename}
                  └── processed/
                      └── clean_dataset.parquet (Day 3+)
```

---

## 4. Storage Security Policies
1. **Presigned Expirations:** Upload URLs expire within 15 minutes of generation.
2. **Size Limits:** Free tier capped at 50 MB per file; Pro tier up to 500 MB.
3. **MIME & Magic Number Verification:** The backend worker validates file headers against declared extensions before processing.
4. **No Direct Public URLs:** Bucket contents are private and accessible only via signed URLs generated by the API layer.
